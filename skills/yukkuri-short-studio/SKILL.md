# ゆっくり縦ショートを複数の AI で作る

このスキルは全体の段取りと決まりだけを持つ。手を動かす部分は2つのスキルに任せる。

| 工程 | 使うもの |
|---|---|
| 音声 | `yukkuri-voice` スキル（台本 → ゆっくりボイス → 聞き取り確認） |
| 編集素材 | `premiere-short-xml` スキル（spec.json → Premiere 用 XML・動く図・BGM・効果音） |
| 分担と管理 | このリポジトリの `tools/studio/studio.py`（tasks.json・brief・報告・看板ボード） |

実例は `examples/nhk-chairman/`（NHK会長編・42秒）。迷ったらその台本・tasks・make_spec.py を見る。

## 0. 最初に読む6行

1. **状態の正本は `tasks.json`。書くのは統括（Claude Code）だけ。** ほかの AI は `tasks/<ID>/brief.md` を読んで `報告.md` を書くだけ。
2. **人の判断が要る作業（👤）は、人が OK するまで完了にしない。** 台本の確定・人物の絵・Premiere での確認・公開。
3. **従量課金の API は、使う前に見積もりを出して承認をもらう。** 見積もりだけならどのスクリプトも課金なし（dry-run）。
4. **上書きしない。** 直すときは版を上げる（台本_v2・premiere/v2・Premiere読み込み用/…_v2）。
5. **事実は一次資料で確かめ、台本を書いたのとは別のモデルに点検させる。** 数字・言葉は資料に根拠のあるものだけ。
6. **「できた」は確かめてから言う。** 聞き取り（Whisper）・見た目（preview_frames）・Premiere の自動保存（inspect_prproj.py）。

## 1. 標準の工程

```bash
mkdir my-short && cd my-short
python3 <repo>/tools/studio/studio.py init --title "受信料の割増金編"
python3 <repo>/tools/studio/studio.py status
```

| 工程 | 作業 | 担当の目安 | 人の判断 |
|---|---|---|---|
| リサーチ | 一次資料を集め、`research/ファクト表.md` と `research/一次資料/`（抜粋）を作る | Claude サブ（researcher） | |
| 台本 | 台本 v1（§2 の決まり） | Claude（統括） | |
| 台本 | ファクトチェック（別モデル・読み取りだけ） | Codex CLI | |
| 台本 | 指摘を反映した v2 → **確定** | Claude → 人 | 👤 |
| 音声 | ゆっくりボイス・読み辞書・聞き取り確認 | Claude | |
| 素材 | 人物・建物の絵（JS Paint） | Codex アプリ（手渡し） | 👤 |
| 素材 | 図（Python で透過 PNG の部品） | Codex CLI | |
| 素材 | 資料のスクショ（法令は e-Gov） | Claude | |
| 編集 | `make_spec.py` → spec.json → `build_all.py` → 動く背景 → 書き出し | Claude | |
| 音 | BGM（ライブラリ or ElevenLabs）・効果音 | Claude | 課金なら承認 |
| 検収 | プレビューの点検（別モデル） | Codex CLI | |

| 公開 | 概要欄・出典・権利の表記 | Claude | |

渡し方：`studio.py dispatch T03` → Codex CLI なら `studio.py run T03`（裏で実行・並べてよい）→ `studio.py sync`（報告を取り込み、受け入れ条件を点検）→ `studio.py approve T03`。Codex アプリや人には `dispatch` が出す依頼文を貼る。看板ボードは `studio.py serve`（人が OK・差し戻し・判断・メモ・カードの追加をする。操作は作業ログに「ユーザー（ボード）」で残る。**統括は次の作業の前に、ボードからの差し戻し・決定・メモを読む**）。

プロジェクトのフォルダには `AGENTS.md`（Codex が読む）と、中身が `@AGENTS.md` だけの `CLAUDE.md` を置き、決まりの正本を1つにする（例：`examples/nhk-chairman/AGENTS.md`）。

## 2. 台本の決まり

- **1本の軸。** 最後の答えを一文で決め、そこへ一方向に進む3〜4段階だけを残す。外した論点は別の回の候補にする
- **高校生でもわかる言葉。** 専門用語は一度だけ出して短い日常語で言い換える。耳で追いにくい割合の比較や擬人化はしない
- **対象（誰・何の話か）は冒頭10秒以内。1行目で題名を読む**（「〜って、知っているか？」）
- **掛け合い**：説明役（まりさ）が事実、聞き手（れいむ）が疑問・驚き・言い換え。振りはすぐ回収する
- **強い言葉は資料の言葉で。** 説明役に断定させず、決議・答弁・条文の言葉を出典つきで言わせる。聞き手の感想は、直前に説明役が根拠を出していれば強くてよい
- **否定の範囲をしぼる。**「選べない」より「直接は選べない」、「一票はない」より「会長選びに、…一票はない」（NHK会長編でファクトチェックが指摘）
- 台本には「言い換えで誤解を生まないための注意」と「根拠」の表を付ける
- 尺の見積もり：声だけ ≒ 字数（句読点を含めて数える）÷ 8.8 秒、通しは＋約8秒。yk.py の表の「字/秒」は句読点を除いた字数で数えるので、同じ台本でも数字が違う（NHK会長編：句読点込み348字で見積もり約40秒 → 実測36.7秒・句読点抜き305字で8.3字/秒）
- 台本を検討している段階では音声を作らない（テキストで往復する）

## 3. 別モデルの点検（2回）

| いつ | 何を | 形 |
|---|---|---|
| 台本 v1 のあと | 事実を言っている箇所をすべて拾い、一次資料の抜粋と照らして「合っている／言い過ぎ／違う／根拠なし」、耳で誤解されそうな言い方と直す案 | 表（行｜台本の言葉｜判定｜根拠の原文｜直す案） |
| 組み立てのあと | 45フレームおきの並べ画像で、重なり・読めない文字・下1/3の出典・台本との食い違い・言い過ぎ | 表（フレーム｜問題｜直す案｜重さ） |

指摘はそのまま全部は入れない。統括が仕分けて、入れないものは理由を書く（例：図の主役を隠さないためにテロップを下げたまま）。一次資料の抜粋はリポジトリの中に置いておくと、点検する側がネットにつながらなくても確かめられる。

## 4. 画面の決まり（縦 1080×1920）

- **下1/3（y1280〜）は操作ボタンで隠れる**：出典・注記・発信者表示の場所。**最上部（〜200）**はラベルだけ
- **テロップは縦の真ん中（y960）が基本。** 人物の顔や図の主役を見せたい拍だけ y1150 に下げる。後ろにグレーの座布団（不透明度40）
- **人物の絵は大きく。** 出てから1秒くらい顔を見せてからテロップを重ねる。顔に意味なく重ねない。初めて出るところに「※イラストはイメージです」
- **注記は左寄せ・意味の切れ目で改行（`\n`）・字は小さくてよい、はみ出さない**（`note_x` 40・`note_w` 880）
- テロップの色：白＝ふつう・黄＝数字や要の語・赤＝人名や一番強い語・ピンク＝聞き手
- 1行9文字前後まで、色が変わるところで段を分ける。セリフ全文は出さない

## 5. 素材

- **人物・建物の絵**：Codex に JS Paint で描かせる。人物は 360×640・透過・べた塗り、**頭の上端の中央を (180, 97) にそろえる**（表情を替えても顔の位置が動かない）。表情は2〜3種（普通・困り顔など）。公式写真の模写・公式ロゴの形は避け、参考にした写真の URL だけ記録する
- **図**：Python（Pillow）で透過 PNG の部品と差分（例：12の席の点灯0〜9）を作り、作ったスクリプトも残す。重ねる部品は同じキャンバスで切り、四隅にほぼ透明の点を打って位置をそろえる（`prep_assets.py`）
- **資料のスクショ**：寄る→マーカー→赤枠→ハンコ。マーカーの位置はページから取り出して記録する（`スクショ/v1/位置.json`）
- **背景は動かす。** なめらかなグラデーションの静止画は寄っても動いて見えない。`make_bg_anim.py`（光の帯・回る放射・漂う粒・BGM の拍の脈・山場の集中線とフラッシュ・区間の頭のワイプ）で区間ごとの動画を作り、spec の backgrounds に `anim: true`

## 6. 編集（premiere-short-xml）

- spec.json は手で書かず `make_spec.py` から作る（時刻に合わせた計算を入れられる。例：席を1つずつ点ける時刻を、実測したテロップの時刻から出す。chars の `{"frame": n}` は項目の頭からのフレーム数）
- 流れ：`build_all.py` → `make_bg_anim.py` → `build_premiere.py` → `preview_frames.py`（重なりの点検）→ `preview_video.py` → `export_package.py`（新しいフォルダ）
- 自分で見て直してから別モデルの点検に回す

## 7. BGM と効果音

- **BGM**：ライブラリの曲なら波形を見て（`analyze_bgm.py`）、曲の「ため→打ち込み」を山場（人物の登場など）に合わせる。ElevenLabs で作るなら、動画の区切りに合わせた構成案（`chunks`：冒頭全開 → ため → ドロップ → 走り続ける → 締め）で2本作って選ぶ（例：`examples/nhk-chairman/音/v2/plan_v2.json`）。締めに曲の頭の一打を置くと、ショートが頭に戻ったときつながる
- **効果音**：拍ごとに置く（聞き手の「？」・ハンコ・マーカー・赤枠・着地・点灯・不成立）。一番大きい事実にだけ「ガーン」。自作の短い音（ピコッ・ブッ・どすん）は numpy で合成できる（権利の問題がない）
- 混ぜたら **Whisper で全行が聞き取れるか確かめる**（BGM はナレーション比 −12〜−16 LU）
- 規約：音源ファイルは再配布しない（リポジトリにも入れない）。政治・宗教の利用を禁じる曲がある

## 8. 刺激を足す（短い注意でも最後まで見られる作り）

1〜2秒ごとに何かが動くようにする：題名と答えの語を回転表示（`motion: spin`）、建物や人物を上から落とす（`drop`）、驚きで顔に寄る（パンチイン）、聞き手の問いの行に背景の大きな黄色い「？」、✗ は揺らす、背景は拍で脈打ち、山場で集中線。やりすぎて文字が読めなくならないよう、テロップの座布団と注記の位置は守る。

## 10. 公開するとき

- 音声・BGM・効果音の音源・Premiere 読み込み用・作業の media はリポジトリに入れない
- 実在の人物の似顔絵を配布素材として公開するかは、動画に入れる判断とは別に決める
- 出典は概要欄に（資料名・日付・URL）。BGM・効果音のクレジットは規約どおりに
