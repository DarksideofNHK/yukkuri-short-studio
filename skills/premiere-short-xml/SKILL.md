# Premiere 用の素材一式を作るスキル

台本（Markdown）＋行ごとの音声（yukkuri-voice の出力など）＋定義ファイル `spec.json` から、Premiere Pro 2026 で「ファイル→読み込み」すればトラック・動き・マーカーまでそろったシーケンスになる素材一式を作る。最初の案件（2026-09）で Premiere に読み込んで確かめながら作った。

## 0. 最初に読む5行

1. **無料・ローカルで完結**（Pillow・ffmpeg・pdftoppm・yukkuri）。課金 API は使わない。
2. **出力は毎回新しいフォルダ**（`premiere_v11/` など）。`build_premiere.py` は出力先の `media/` を消して作り直すので、ユーザーが Premiere で使っている既存のフォルダには書かない。**別のセッションが同じフォルダを触っていないか**（数分以内の更新がないか）を先に見る。
3. **音声は yukkuri-voice スキルで作る。** その出力フォルダの `manifest.json` を spec の `audio.manifest` に指せばそのまま読める。台本の行と音声の文が1字でも違うと止まる（作り直すか台本を合わせる）。
4. **Premiere で確かめるまでは「できた」と言わない。** 読み込み後の結果は、ユーザーにスクショを頼まずに自動保存（.prproj）を `inspect_prproj.py` で読んで確かめられる（6章）。
5. 画面に出す数字・言葉は資料に根拠があるものだけ。ハンコ・マーカーの文言も資料の言葉から取り、出典（資料名・ページ・日付）を注記に出す（`references/design_rules.md`）。

## 2. 標準の流れ

1. 台本（```の中に「`番号 話者：セリフ`」）と音声フォルダ（`manifest.json`）を確かめる
2. 新しい出力フォルダを作り、`assets/example_spec.json` をひな形に設定を書く（`references/spec_format.md`）。サンプルのパスは `examples/nhk-chairman/` で始まるため、設定をリポジトリ直下へ `spec_nhk_v2.json` など未使用の名前でコピーする。別の場所に置くなら、その設定ファイルからの相対パスに直す
   - `lines`：行ごとのテロップ。`anchor`（ナレーションのどの言葉で出すか）と `lines`（1行1色）
   - `v2`：`chart`（グラフ）・`shot`（スクショの動き）・`slot`（差し替え枠）・`quote`（引用カード）
   - `notes`（出典）・`backgrounds`（背景の仮）・`title_card`・`end_card`・`label`
   - `chars`（任意）：人物のイラスト。絵は作業フォルダの `chars_src/` に写して相対パスで書く（`references/spec_format.md` の「イラスト」、置き方と風刺の線は `references/design_rules.md`）
3. 実行（リポジトリ直下で。`--out` は新しいフォルダを指定）

   ```bash
   python3 skills/premiere-short-xml/scripts/build_all.py --spec spec_nhk_v2.json --out examples/nhk-chairman/premiere/v2
   ```

4. 自分で確かめる：`preview_video.py`（全体の流れ・ナレーション入り。ユーザーにもこれを送る）、`preview_frames.py`（テロップ・図・注記・イラストの重なり）、`media_anim/プレビュー_V2.mp4`（動き）、`media/02_図・スクショ・グラフ/V2_SH*_スクショ.png`（マーカーが資料の文字に乗っているか）、`timeline.json` の `units`（テロップの時刻）
5. 読み込み用フォルダを書き出して渡す（作業フォルダの XML を直接渡さない。作業用のファイルが混ざって分かりにくいため）

   ```bash
   python3 skills/premiere-short-xml/scripts/export_package.py --spec spec_nhk_v2.json --out examples/nhk-chairman/premiere/v2 \
     --dest "examples/nhk-chairman/Premiere読み込み用/_NHK会長編_v2_BGMなし" --name NHK会長編_v2_BGMなし
   ```

   中身：`00_これを読み込む_{name}.xml`・`01_はじめに読む.md`・`02_素材リスト（差し替え・出典）.md`・`素材/01_ナレーション/…`（ビンと同じ名前）・`確認用/動きの確認_図・スクショ・グラフ.mp4`。**既にあるフォルダには書かない**（ユーザーが読み込んだ素材を入れ替えてしまうため）。作り直したら版の番号を上げた新しいフォルダにする。ユーザーには「新規プロジェクトの保存場所をこのフォルダに」と伝える
6. ユーザーに伝える：フォルダの場所、読み込んだ後に見てほしい点（初めての機能だけ）、自分で入れる差し替え枠
7. 読み込まれたら自動保存を読んで結果を確かめる（6章）

音声を作り直したら、spec の `audio.manifest` を新しいフォルダに向けて `title` を変え（別のシーケンスになる）、`build_all.py` を流すだけ。テロップの時刻・グラフとスクショの動きは全部新しい音声に合わせ直される。

## 3. テロップ（文字クリップ）

- 既定は `telop_mode: "text"`：FCP7 の Outline Text ジェネレーター → Premiere ではエッセンシャルグラフィックスの文字レイヤー（打ち替え・書体・色の変更ができる）。塗りの色・黒の縁取り（外側）・スケールのキーフレームは読み込まれる（2026-09-26〜27、Premiere で確認）
- **1行1クリップ。** Premiere は複数行の文字を1行ずつ別のレイヤーに分け、行数だけで位置を決め直す（空行も1行と数え、行の間隔は文字サイズと同じ）。行数の違うクリップを重ねると段がずれて重なるので、テロップの各行を別のクリップにして、行ごとの高さを `origin`（原点）の縦の値で指定する（行1＝V4、行2＝V5、行3＝V6、聞き手は V7・V8）
- 位置の決まり（縦 1080×1920 で実測）：1行のクリップは origin 0 で、文字の下端（ベースライン）が **960 −（サイズ/8 + 2）** に来る（104px なら 945）。origin の縦 v で **v × 1920 px** 下がる。build_premiere.py は、テロップ全体を `telop_block_y`（縦は 1060。common.py）を中心に、行の間隔 `line_pitch`（1.2 × サイズ）で積む。テロップ1枚だけ高さを変えるときは、そのテロップ（`title_card` も可）に `"y": 960` のように中心の高さを書く（960＝画面の縦の真ん中。実際の制作で題名をこの位置に置いた）
- **Basic Motion の center（位置）は文字クリップには効かない**（読み込まれない）。位置は origin で決める
- **フォント名は PostScript 名（空白なし）**：`HiraMinProN-W6`。空白を含む名前は読み込みで壊れる
- **文字サイズは px ÷ text_scale** で書く（縦 1080×1920 は 4.0：FCP の 26 → Premiere 104px）。縁取りも同じ（3 → 12px・外側）
- 長い行は自動で小さくして画面幅（980px）に収める
- **座布団**（spec の `telop_box`）：テロップ1枚ごとにグレーの角丸を後ろ（V4）に置く。不透明度は XML の Opacity（既定40＝透過率60％）で、Premiere で変えられる。テロップの高さを動画ごとに変えるときは `layout_overrides: {"telop_block_y": 1150}`（実際の制作で決めた型：顔は図のすぐ下に1.5倍、テロップは胸から下。`references/design_rules.md`）
- 見た目の目安は `preview_frames.py --frames 10,170,800`（Premiere と同じ置き方で行を描いた並べ画像）で、読み込み前に重なりを点検する
- `telop_mode: "image"` にすると従来の画像テロップ（語ごとの色分け・影つき・打ち替え不可）

## 4. スクショの動き（shot）

資料（PDF のページか画像）をカードにして、目印の言葉に合わせて動かす：出てくる → 寄る（`view`）→ マーカーを左から引く（`mark`、複数行は順に）→ 赤枠（`box`）→ ハンコ＋揺れ＋白く光る（`stamp`）。ずっと少しずつ寄る（`drift`）。資料名の帯（`caption`）を左上に出す。

1. PDF はページの座標（ポイント）で指定する。`pdftotext -f N -l N -bbox-layout 資料.pdf out.html` で行の枠（xMin, yMin, xMax, yMax）を出し、語の範囲は「行の幅 ÷ 文字数 × 何文字目」で見積もる
2. 一度 `build_premiere.py` を流すと `media/02_図・スクショ・グラフ/V2_{id}_スクショ.png` に最後の状態（全部のマーカー・赤枠・ハンコ）が出るので、**必ず目で見て**マーカーが語に乗っているか確かめて直す
3. 公開サンプルでは e-Gov の法令条文の必要部分を使う。元画像の寸法に合わせて座標を測る。案件専用のスクショ加工スクリプトは同梱しない。番組映像・公式ロゴの形・報道写真・公式写真そのものやトレースは使わない
4. `at` は目印の言葉（その図の最初の行）か `{"line": 5, "anchor": "9人以上"}`、行の頭は `{"line": 2}`
5. ハンコの文言は資料の言葉に根拠のある短い語（「九人以上」など）。下の小さい字（`sub`）に出典と日付

## 5. タイミング

- 各行の音声は `start_offset_sec` から `gap_sec` あけて並べる。テロップは目印の言葉が読まれる時刻の `lead_frames`（2）前に出て、次のテロップが出るまで残る
- 目印の時刻は、**目印の手前までを同じ声・同じ話速で yukkuri に読ませた長さ**で測る（yukkuri v2 の音声のとき）。結果は出力先の `anchor_times.json` にためる（音声の `request_hash` と文字位置がキー）。前の版の `anchor_times.json` を写しておけば測り直さない。yukkuri がないときは文字数の比例で見積もる（`timeline.json` の `units[].timing` が `estimate`）
- グラフの `on` 番号は「その図の範囲の何番目のテロップか」。**テロップの数を変えるとグラフの動きがずれる**ので、行を分ける（段を増やす）のはよいが、テロップの数は変えない（変えたら `on` を直す）

## 6. 読み込み後の確認（自動保存を読む）

ユーザーが XML を読み込むと、数分でプロジェクトの隣の `Adobe Premiere Pro Auto-Save/` に自動保存ができる。

```bash
python3 skills/premiere-short-xml/scripts/inspect_prproj.py "<プロジェクトのフォルダ>" --grep 経営委員会
```

文字（改行は ⏎）・フォント名・数値（サイズ・縁取りの候補、×4 されているか）・位置が出る。フォント名が PostScript 名のままか、2段目以降の空行と改行が効いているかをここで確かめる。元の .prproj には書かない（読むだけ）。

**ユーザーが Premiere で手直ししたところ**（クリップの長さ・位置・大きさ・足したクリップ・打ち替えた文字）は `inspect_sequence.py` で読む。XML を読み込むと同じ名前のシーケンスが2つできることがあり、`--diff` で「読み込んだまま」と「手直しした方」の違いだけが出る。次の版の spec に取り込むときに使う（実際の制作で、スクショの短縮・テロップの追加・大きな「？」・テロップの上下を取り込んだ）。

```bash
python3 skills/premiere-short-xml/scripts/inspect_sequence.py "<プロジェクト.prproj>" <シーケンス名> --fx --text --diff
```

## 7. 横版（1920×1080）

`"layout": "horizontal"`。テロップは下寄り、図は右寄り。**横の text_scale（2.25）は未確認**なので、最初の横版は小さな試験（文字クリップ2〜3個）を読み込んでもらい、`inspect_prproj.py` でサイズを確かめてから本番を作る。

最初の横版は実際の制作（2026-09-27）で試した。検証用シーケンスには目盛りの背景を置き、文字サイズ・origin の縦と横を同時に見る。テレビで見る前提の置き方：左に表（chars の役者として置いた絵。`hold: true` でエンドカードまで残す）・右に図（`layout_overrides` の `shot_area` [900,84,1860,720]・`panel` [930,110]・`panel_scale` 1.0）・テロップ `telop_block_y` 838・注記 `note_y` 995／`note_size` 30／`note_w` 1760・ラベル `label_pos` [40,18]。`preview_frames.py` は横なら 640 幅で並べる。

## 8. BGM を足す（波形を見て合わせる）

最初の案件（2026-09-27）で作った手順。書き出し済みの読み込み用フォルダに、あとから BGM を足す。

1. **曲の規約を先に見る。** 用途・クレジット・再配布条件を確認する。題材固有の注意は `references/design_rules.md` の付録を参照。サンプルでは利用者が用意した ElevenLabs Music の曲を使い、このスキルから課金 API は呼ばない
2. `analyze_bgm.py 出力フォルダ 曲.mp3 …` で波形の図を出して**目で見る**。立ち上がり・「ドン」と入るところ・途切れる区間・自然に終わるところを探す。2秒幅の区切り目は目安なので、使う位置は ±0.8 秒を 10ms 刻みで測り直す（ファイル頭の無音のせいで「2.0 秒」に出る区切りは無視）
3. ナレーションの区切り（`timeline.json` の lines）と曲の出来事を1対1で決め、曲の何秒から使うか（`in_sec`）を「曲の出来事の秒 − 合わせる行の頭の秒」で出す
4. リポジトリ直下で設定（`assets/example_bgm.json`）を書いて `add_bgm.py 設定.json` → `add_bgm_docs.py 設定.json`
   - 新しいフォルダは `cp -c`（APFS のクローン）で作るので容量をほぼ使わない。元のフォルダには書かない
   - **既定（handles）：曲の頭から終わりまでを1つの WAV にし、タイムラインには使う区間だけを in/out で置く**（2026-09-27 ユーザー指示「BGM は後からタイムラインで伸ばせるように」。前は使う区間だけを切り出していたので伸ばせなかった）。音量と `lifts`（曲の中の位置で持ち上げ）は WAV に焼き込み、入り・終わりのフェードは XML のオーディオトランジション（Cross Fade (+3dB)＝コンスタントパワー）。同じ A3 で2曲が重なると上書きされるので止まる → 前の曲の `end_f` を後の曲の `start_f` にそろえると、つなぎ目の真ん中に1つのクロスフェードが入る（両側に曲の余白があるので可能）。`"handles": false` で前の形（切り出し＋フェード焼き込み）
   - 音量は、ナレーション（実測 LUFS）より `target_rel`（−16）LU 小さく、短期の最大は `cap_rel`（−9）LU まで。形式はナレーションと同じモノラル 48kHz 16bit、長さはフレームの整数倍（in 点がフレームの境目に来るよう頭に無音を足す）
   - `start_f`・`end_f`・`in_sec`・`lifts` には `K`（聞き手の決め台詞の頭）・`F`（最後の行の頭）・`E`（エンドカード）・`Z`（終わり）が使える
5. spec を直して作り直したときは `preview_video.py` も流す（`build_all.py` は確認用の動画を作らないので、写した作業フォルダの古い動画がそのまま書き出される）。`確認用/BGMの配置_波形.png`（ナレーション・BGM・合わせた位置）を見て確かめ、`確認用/全体の流れ_目安_BGM入り.mp4` をユーザーに渡す
6. 読み込まれたら、A3 に曲が並び、声とのバランスが合っているかを確かめる（最初の案件で A3 の WAV、handles の in/out と XML のオーディオトランジションを読み込めた。トランジションは Premiere では「カスタムフェード」になる。`references/premiere_xml_notes.md`）
   - `K` を使わない場合は `F`・`E` などで区切る。最後の説明を声だけにするなら `F-3`、サンプルのようにエンドカードまで曲を続けるなら `E` で本編を終える（設定の `ending_note` で説明も変える）
   - **`E` は XML の「エンドカード…」クリップの頭から読む。spec の `end_card` から `sender` を外すとそのクリップがなくなり、`E` が終わり（`Z`）に落ちて締めのピアノの位置がずれる**（実際の制作で起きた）。外した回は `E` を「終わり − end_card_sec×fps」の数字で書く（例：`"6.5-(1534-(F-3))/fps"`・lifts `[["1534", 0], ["1534+9", 6]]`）。add_bgm の1行目に出る「エンドカード ◯f」が前の版と同じかを必ず見る

NHK会長編の実例：曲の14.41秒のドロップを会長登場の405フレームに合わせ、`in_sec: 0.91`（30fps）から再生する。本編は `E` まで続け、エンドカード `E`〜`Z` で同じ曲の頭の一打を使い、40フレームで消す。声との相対音量は `target_rel: -12`・`cap_rel: -6`。音源は別途用意し、配布条件を確認する。

BGM・効果音の設定にあるパスはリポジトリ直下からの相対パス。`example_se.json` の `file` は `<効果音フォルダ>/…` を実際の音源の場所に置き換える。自作音（どすん・ピコ・ブッ）はサンプルの `音/v1/自作/` にあり、スクリプトで作り直せる。`timeline` はサンプルの `premiere/v1/timeline.json`（リポジトリには入っていない。build_all.py を流すと作られる） を指しているため、再生成した場合はその出力先に変更し、フレーム指定の位置も確認する。

### 効果音（A4）

`add_se.py 設定.json`。置く位置は `{"stamp": "明記"}`（ハンコが揺れて光るフレーム＝step の f＋2）・`{"line": 9}`（行の頭の2フレーム前）・`{"frame": 517}`（イラストの shake・swap・hop などのフレーム）。音のいちばん大きいところをそのフレームに合わせ、音量は「ナレーション比 `rel` LU（瞬間の最大）」と「ピーク −6 dBFS」の小さい方で焼き込む。使い方の例：効果音ラボの ペタッ（ハンコ）・ハリセン（聞き手のツッコミ）・えっ（？・首かしげ）・驚く（汗・目そらし）・キラッ（赤枠）・ガーン（いちばん大きい事実に1回だけ）などを要点に合わせる。NHK会長編では席の点灯に短い自作音を9回置き、締めにも効果音を置いている。個数や締めへの使用は内容に合わせて決める。BGM の大きな一打と2フレーム以内で重なるところは効果音をやめる。Premiere に読み込み済みのフォルダには書かない（止まる）。

## 9. つまずいたとき

| 症状 | 原因と対処 |
|---|---|
| 「フォントを解決」が出る | フォント名に空白がある／その Mac にない。PostScript 名にする。読み込み後なら「グラフィックとタイトル」→「プロジェクト内のフォントを置換」 |
| 文字がとても大きい | text_scale で割っていない（FCP のサイズは ×4 される） |
| グラフ・スクショが静止画になる | 動画の長さがクリップと合わない → `build_all.py` を流し直す |
| 台本と音声の文が違うと止まる | 音声を作り直すか、台本の行を音声に合わせる |
| SRT の字幕 | 読めるが画面下に字幕として出るだけ。テロップには使わない（ユーザー判断 2026-09-26） |
